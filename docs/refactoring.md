# 会战服务重构

本次保留现有 QQ 命令、网页 API 与已有 SQLite 表，拆出会战服务、状态模型、权限与文件访问边界，并追加报刀撤销快照表。

## 模块职责

- `ybplugins/templating.py`：静态资源 URL 包含文件内容摘要，同一版本内更新脚本后也会刷新浏览器缓存，避免新模板与旧脚本混用导致页面空白。

- `ybplugins/boss_data.py`：获取并校验 Boss 数据，排除训练阶段，转换正式周目范围。默认只接受当月；数据源尚未发布时，页面显示最新可用月份，需勾选“允许使用最近一期”才会采用往期数据。两服独立获取，全部失败不写配置，头像失败不影响已保存的数据。

- `components/battle_service.py`：报刀、撤销、清空与切换档案。报刀先完成校验，再更新记录、血量、申请和预约。
- `components/battle_state.py`：统一完整刀/补偿刀计算及事务边界。同步会战写操作刷新数据库状态，在同一事务中保存；异常恢复数据库和缓存；网页更新和群通知在提交后执行。
- `components/challenge_state.py`：`ApplicationState` 与 `ChallengeState` 表达申请、补偿、预报伤害、挂树和备注，集中处理成员状态转换，保留原 JSON 字段及未知扩展字段。
- `components/report_undo.py`：持久化报刀前后状态，按本次报刀的变化恢复，保留无冲突的后续申请与预约。
- `ybplugins/permissions.py`：机器人主人使用全局身份；公会管理员使用目标公会的成员角色。全局设置只允许主人。
- `ybplugins/file_access.py`：静态文件读取、gzip 缓存与资源缓存均限制在各自根目录。

`realize.py` 保留原方法入口，QQ 和网页通过同一服务处理报刀与档案操作。服务必须拥有最外层事务；在外部已经打开的数据库事务中调用会报错，避免保存点释放后提前发送通知。

## 行为修正

- 失败报刀保留原申请、挂树、预报伤害与备注。
- 新报刀支持完整撤销：恢复血量、周目、原申请、挂树、预报伤害和预约备注；刀数及补偿从删除后的记录重新计算。重启后快照仍可使用。
- 后续操作若修改了需要恢复的状态，撤销会明确拒绝；也会拒绝产生同一成员的双重申请、改变后续申请的目标周目或将血量恢复到错误周目。拒绝时保留记录、快照和当前状态。
- 旧报刀记录不补造历史快照，仍可撤销血量和刀数，并显示限制说明。撤销更新会战状态，不撤回已发送的通知。
- 挂树查询只检查指定成员，修复原先可能返回其他成员挂树状态的问题。
- 清空历史档案不会重置当前进度，同时移除该历史档案的状态备份。
- 昨日报刀按昨日记录检查补偿刀。
- 网页报刀、撤销响应使用提交后的状态。
- 本公会权限不再因其他公会的管理员身份而提升；取消全部申请限群管理员或主人。
- 群通知异常不会把已经保存的报刀显示为失败。通知会记录错误，但本轮未增加持久化通知重试队列。
- 公共文件路由拒绝目录穿越；安全令牌使用 `secrets`。
- 异步缓存到达容量上限后继续正常工作；启动网络请求设置超时。
- 显式声明图片模块使用的 `httpx==0.27.2`，兼容现有 `proxies` 参数。
- 统计页面的均值偏差与多维分析外部服务已停用，入口禁用且不再向其传递公会 API 地址和密钥；站内图表、出刀顺序及原始数据下载保留。API 禁用时不渲染复制密钥的脚本。
- 图表页使用已随项目提供的本地 ECharts 文件。

## 验证

```sh
python -m venv .venv
# Linux/macOS: .venv/bin/python；Windows: .venv/Scripts/python.exe
.venv/bin/python -m pip install -r src/client/requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

测试使用临时目录、隔离 SQLite 数据库和真实 Quart 路由，不需要 QQ 登录，也不访问生产数据。CI 在 Linux 与 Windows 上运行，使用本次本地验证的 Python 3.9；这不是对运行时长期支持的承诺。

## 部署与后续边界

部署应从这个 fork 的源码构建；原来的自动安装脚本仍引用原版 `yobot/yobot` 镜像，不能用它验证本次改动。

升级前备份数据目录，包括数据库及其 WAL 数据，优先在机器人停止后备份。先用测试公会验证命令、补偿与群通知，再替换实际服务。本轮没有启动真实机器人或构建 Docker 镜像。

启动时数据库版本自动升级到 4：版本 2 及以下补建 `Clan_challenge_undo` 表和索引，版本 3 及以下在报刀表新增可空的 `return_seconds` 返秒字段。旧报刀及成员数据保留，旧尾刀返秒字段为空，按原尾刀阶段显示：B/C为90s，D为?s。升级失败时事务回滚。旧程序会拒绝打开版本 4 的数据库；回退程序应同时恢复升级前的数据备份，不要手改版本号。

仍需单独处理运行时及依赖升级、登录会话撤销、自动备份恢复入口、持久化通知重试，以及多实例的网页长轮询与只读缓存同步。现有 Docker 基础镜像和旧框架的升级需要兼容性验证，本轮不与会战服务迁移混做。
